HOW TAXSYNC ARCHITECTURE WORKS

AI-powered document management + Indian-regulator compliance tracker. v2.1.1 · 502+ tests green

★ REMEMBER

  • 3-tier service: web → API → DB
  • Async: HTTP 202 + Celery
  • Multi-tenant via RLS
  • JWT + opaque refresh
  • Docker for everything

1 WHAT IS TAXSYNC?

Multi-tenant SaaS that ingests documents (PDF, image, DOCX), runs OCR + ML classification, then layers a 4-stage compliance approval workflow for Indian regulatory notices (GST · IT · MCA · RBI · SEBI).

USER ─► UPLOAD ─► OCR ─► CLASSIFY ─► STORE
                                  ▼
                          SEARCH / WORKFLOW
                                  ▼
                  ALERTS · APPROVALS · REPORTS

Built for IIIT Hyderabad Production Labs. v1.0 shipped doc management; v2.0 added compliance; v2.1 added BYOK AI + per-tenant branding.

6 MULTI-TENANCY MODEL

  • Shared schema, one DB
  • Every tenant table has client_id
  • Row isolation = Postgres RLS
  • Tenant resolved per-request via header X-Client-Id
  • Listener pins SQL session vars BEFORE the route runs
  • Cross-client mode X-Client-Id: * only for senior auditors
  • No tenant header ⇒ fail-closed (zero rows)

11 KEY ARCHITECTURAL DECISIONS

DecisionWhy
Shared DB + RLS, not DB-per-tenantCheaper at scale; less ops overhead; one migration set
Session-mode Supabase poolerRLS context vars don't survive transaction pooling
before_cursor_execute listenerset_config + SET ROLE are tx-local; rebind per statement
Two Celery queuesHeavy ML never starves v1.0 OCR; 2 GB cap on ML worker
BYOK LLMCosts hit tenant's provider account; TaxSync never bills
Audit immutability via DB triggerDefense in depth even against compromised app role
Soft-delete onlyAudit-log trigger forbids row removal
