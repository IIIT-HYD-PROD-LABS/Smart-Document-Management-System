## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps inside compact buttons (gap-1), tight inline padding |
| sm | 8px | Compact element spacing (px-2 py-2), pill badge horizontal padding |
| md | 16px | Default element spacing, card content padding (p-4), table cell vertical padding |
| lg | 24px | Card body padding (p-5/p-6), section padding inside dashboard panels |
| xl | 32px | Layout gaps, dashboard column gaps (gap-8), spacing between filter sidebar and table |
| 2xl | 48px | Major section breaks, wizard step pane vertical breathing room |
| 3xl | 64px | Page-level top spacing, empty-state illustrations |

**Tailwind mapping:** xs=`gap-1`, sm=`p-2`, md=`p-4`, lg=`p-6`, xl=`gap-8`, 2xl=`p-12`, 3xl=`p-16`.

**Exceptions:**
- **Touch targets:** Icon-only buttons (bulk action bar, notice row checkbox area, dropdown trigger) MUST have a 44px x 44px minimum hit area, even when visual icon is smaller — implemented via `p-2.5` (10px) on a 24px icon = 44px. WCAG 2.2 Target Size Minimum requires 24px CSS pixel minimum; we use 44px to align with iOS HIG and Android Material guidance.
- **Status badge vertical padding:** `py-1` (4px) is permitted for inline badges to keep table row height compact at 48px (table cell content is ~32px text + 16px vertical padding). This matches existing v1.0 `StatusBadge.tsx`.
- **Floating bulk action bar:** Bottom inset is 24px from viewport bottom; horizontal inset auto-centered, max-width 720px. NOT a multiple-of-4 exception — already on the scale.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 (21px) |
| Label | 11px | 500 (medium) | 1.4 (15px) — uppercase, tracking-wider for stat card labels and table headers (matches v1.0 admin pattern) |
| Heading | 18px | 600 (semibold) | 1.3 (23px) — page titles e.g. "Compliance Dashboard", "Onboard New Client" |
| Display | 24px | 600 (semibold) | 1.2 (29px) — stat card values (`text-2xl font-semibold`), notice number on detail page |

**Typography rules:**
- Exactly **4 sizes**, exactly **2 weights** (regular 400, semibold 600). No `font-bold` (700+), no `font-thin` (300-).
- **Caption sizes 12px / 13px** (text-xs / text-[13px]) used in v1.0 for table cell secondary text and nav labels are permitted as a single shared "caption" role under Body — they share weight 400 and line-height 1.5. They are NOT additional declared sizes; they are display variants of Body for tertiary info (e.g., joined-date column, nav menu items).
- **All text on dark surfaces.** White (`#ffffff`) for primary text, `#a1a1aa` (zinc-400) for secondary, `#71717a` (zinc-500) for tertiary, `#52525b` (zinc-600) for placeholder/disabled.
- **No italic.** No underlines except on hover for link affordances.
- **Numbers** in stat cards, financial fields (tax_demand, interest, penalty, total_liability), and risk scores use `tabular-nums` for column alignment.

**Tailwind mapping:**
- Body: `text-sm font-normal leading-[1.5]` (Tailwind text-sm = 14px)
- Body caption: `text-xs` (12px) or `text-[13px]` for table cells; same weight/leading
- Label: `text-[11px] font-medium uppercase tracking-wider`
- Heading: `text-lg font-semibold leading-snug`
- Display: `text-2xl font-semibold leading-tight`

### Status Workflow Visual Treatment (5 statuses + 2 terminal)

Per D-03 state machine: Received → Under Review → Response Drafted → Submitted → Resolved or Dismissed.

| Status | Hex | Background | Text | Icon | Note |
|--------|-----|------------|------|------|------|
| Received | `#3b82f6` | `bg-[#3b82f6]/10` | `text-[#3b82f6]` | `FiInbox` | Default on creation |
| Under Review | `#f59e0b` | `bg-[#f59e0b]/10` | `text-[#f59e0b]` | `FiEye` | In-progress |
| Response Drafted | `#8b5cf6` | `bg-[#8b5cf6]/10` | `text-[#8b5cf6]` | `FiEdit3` | Awaiting submit |
| Submitted | `#06b6d4` | `bg-[#06b6d4]/10` | `text-[#06b6d4]` | `FiSend` | Pending authority response |
| Resolved | `#10b981` | `bg-[#10b981]/10` | `text-[#10b981]` | `FiCheckCircle` | Terminal — green |
| Dismissed | `#ef4444` | `bg-[#ef4444]/10` | `text-[#ef4444]` | `FiXCircle` | Terminal — red |
| Overdue overlay | `#ef4444` | inline icon | `text-[#ef4444]` | `FiAlertTriangle` | Overlaid on any non-terminal status when `response_deadline < now()` — does NOT replace status, ADDS a red `FiAlertTriangle` icon left of the badge |

**Status workflow visualization (notice detail page LEFT column):** Horizontal pill chain showing all 5 progressive statuses + 2 terminal alternatives. The current status pill is filled in its semantic color; future pills are outline-only (`border border-[#27272a] text-[#52525b]`); past pills show a small checkmark inside the pill in the success color. The line connecting pills uses `bg-[#27272a]` for unwalked transitions and `bg-[#10b981]` for walked transitions. State machine guard: clicking a forward-only allowed transition shows the next-status button with accent color; an INVALID transition shows the button disabled with tooltip "Cannot move from Submitted directly to Received — file an Appeal first". The two terminal states (Resolved/Dismissed) render as a fork at the end, not a sequence.

**Voice & tone rules:**
- **Sentence case** for buttons and headings (not Title Case). "Upload notice" not "Upload Notice".
- **No em dashes** in body copy or buttons. Use periods or commas.
- **No exclamation marks** in error or empty states. Reserve for celebratory toasts only ("Onboarded!").
- **Active voice, second person** ("You don't have access" not "Access denied"). 
- **Specific, not vague** ("Notice number must be 15 characters" not "Invalid format").
- **No emojis in product UI** — they exist only in landing page and `categoryEmoji` v1.0 admin record (which is being preserved unchanged).
- **Indian context**: Currency in INR (`₹` symbol or "INR"), dates in `dd MMM yyyy` per existing v1.0 admin pattern (`day: "numeric", month: "short", year: "numeric"` with `en-IN` locale), GSTIN/PAN in uppercase auto-format on input.

## Accessibility (WCAG 2.2 AA — non-negotiable)

| Criterion | How Phase 9 satisfies it |
|-----------|--------------------------|
| 1.4.3 Contrast (Minimum) | All text ratios verified above. Placeholder color (`#52525b`) restricted to non-semantic UI. |
| 1.4.11 Non-Text Contrast | All borders, focus rings, status dots, and icons meet 3:1 against background. Tier dots use solid color (not relying on hue alone — paired with text label). |
| 2.1.1 Keyboard | All interactive elements reachable via Tab; bulk action bar buttons in tab order. Wizard steps are accessible via "Continue" / "Back" buttons (no required mouse). Dropdown menus open with Enter/Space, navigate with arrow keys, close with Esc. |
| 2.4.7 Focus Visible | `:focus-visible` ring `ring-2 ring-[#3b82f6]/40 ring-offset-2 ring-offset-[#09090b]` on all interactive elements. Focus order matches visual order. |
| 2.4.11 Focus Not Obscured (Minimum) — WCAG 2.2 NEW | Sticky topbar + floating bulk action bar do NOT obscure focused elements; `scroll-margin-top` and `scroll-margin-bottom` on focusable cells ensure focused row scrolls into view. |
| 2.5.8 Target Size (Minimum) — WCAG 2.2 NEW | All interactive targets ≥ 24x24 CSS pixels. Phase 9 baseline is 44x44 for icon-only buttons (well above minimum). Inline links in body text are exempt per spec. |
| 3.3.1 Error Identification | Form errors render below the field with `text-[#ef4444]` and an `FiAlertCircle` icon — color is NOT the only indicator. |
| 3.3.7 Redundant Entry — WCAG 2.2 NEW | Onboarding wizard restores from Zustand persist on refresh; user is not asked to re-enter previously entered values. |
| 3.3.8 Accessible Authentication (Minimum) — WCAG 2.2 NEW | No CAPTCHA introduced in Phase 9; v1.0 auth flow unchanged. |
| 4.1.3 Status Messages | Toasts use `role="status"` (success) and `role="alert"` (error). Bulk action progress uses `aria-live="polite"`. |

## Interaction Choreography

| Surface | Interaction | Animation |
|---------|-------------|-----------|
| Bulk action bar | Mount when selection > 0 | Slide up 200ms ease-out from `translate-y-[120%]` to `translate-y-0`; opacity 0 → 1 |
| Bulk action bar | Unmount when selection = 0 | Slide down 150ms ease-in |
| Client switcher | Open dropdown | Fade + scale 100ms ease-out (`scale-95` → `scale-100`, `opacity-0` → `opacity-100`) |
| Status workflow | Advance state (optimistic) | Pill fills with success color 200ms; checkmark fades in 150ms; row in audit log slides in from top of timeline |
| Wizard step | Continue (next step) | Current pane fades out 150ms; next pane fades in 150ms (no horizontal slide — too much motion for forms) |
| Forbidden state transition | Click forbidden button | Button shakes 300ms (`translate-x-[-4px]` → `4px` → `0` x 3); tooltip appears below |
| Toast | Mount | Slide down from top 180ms; auto-dismiss 4s for success, 6s for error, 0s (manual close) for partial-failure |
| Row hover | Mouse over notice row | `bg-[#18181b]/50` background fade 100ms; cursor pointer |
| Modal / dialog | Open | Backdrop fade 100ms; modal scale-95 → scale-100 + fade 150ms |

**Reduce motion (`prefers-reduced-motion: reduce`):** All animations above swap to instant transitions (`transition-none`); only opacity and color changes remain. No transform/translate.

## Mobile / Responsive Breakpoints

| Breakpoint | Behavior |
|------------|----------|
| `<sm` (< 640px) | Sidebar collapses to drawer; notice table → card list (each notice as a stacked card with metadata); bulk action bar full-width pinned bottom; wizard steps render vertically (one column); two-column notice detail collapses to single column (LEFT first, RIGHT below) |

## Open Items for Planner / Executor

These are NOT design ambiguities — they are implementation choices the planner / executor will resolve:

1. **Recharts vs custom SVG for stat card sparklines:** Phase 9 stat cards do NOT include sparklines (deferred to Phase 13 reporting). If a stat card needs a trend visualization, use `recharts` 2.12.7 (already in stack).
2. **Filter sidebar persistence:** Should filter state persist across navigation? **Recommend:** URL search params (per RESEARCH Pattern hybrid recommendation) — survives back button and refresh.
3. **Date picker library:** v1.0 doesn't have a date picker yet. Use `react-day-picker` v8 (Tailwind-friendly, headless, accessible). Custom-styled to match the zinc/neutral palette. Add to stack in Phase 9.
4. **CSV export format for bulk action:** Standard CSV with columns matching visible table columns. Use `papaparse` v5 for client-side generation (notices count expected < 10K per client at v2 scale).
