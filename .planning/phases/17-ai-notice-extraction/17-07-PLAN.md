## Smoke contract (per D-32)

The smoke runs from inside the backend container so it inherits the same `DATABASE_URL`, `FERNET_KEY`, and Python environment as the live app:

```
docker exec smartdocs-backend python /app/../scripts/smoke_phase17_v20.py
```

CI safety: if `ANTHROPIC_API_KEY_SMOKE` is not set, the smoke prints a single `SKIPPED` line and exits 0. This matches the Phase 15 convention for OAuth-dependent smokes and keeps CI green on machines without provider credentials.

### Checks (numbered, all must pass when key is present)

1. `alembic_head` — Phase 17 migration applied (`0034_phase17_notice_extraction`).
2. `columns_present` — `compliance_notices` carries all five Phase 17 columns plus the two CHECK constraints (status enum, confidence range).
3. `permission_registered` — `CompliancePermission.NOTICE_AI_EXTRACT` exists and is granted to `compliance_head`, `ca_consultant`, `staff`.
4. `byok_412_when_no_credential` — `extract_notice_fields` raises `NoticeExtractionCredentialMissingError` for a tenant without an `AICredential` row (D-14).
5. `extract_real_call` — Real Anthropic call against the fixture GST DRC-01 sample returns a parseable envelope; at least four of {notice_number, authority, issued_date, response_deadline} are present.
6. `routing_gate_apply` — `route_or_apply` returns `action='apply'` when the envelope clears the conjunctive 0.85 gate (D-06). The smoke does not contrive a low-confidence path because real provider runs can drift; the routing logic is exhaustively unit-tested in `test_routing_gate.py`.
7. `persist_envelope` — `apply_extraction_to_notice` writes envelope, confidence, provider, timestamp, and `extraction_status='completed'` onto the fixture notice row.
8. `audit_redaction` — Exactly one `notice_ai_extract` audit row exists for the call; `details` carries `provider`, `model`, `tokens_in/out`, `latency_ms`, `average_confidence`, `body_sha256` and a `fields_returned` key list, and contains NEITHER the raw text NOR any extracted field value (D-16).
9. `accept_audit_per_field` — Calling `accept-extraction` writes one `notice_ai_extract_accepted` audit row per accepted field. Each row's `details` contains `field`, `original_value_sha256`, `accepted_value_sha256`, and `was_edited`. No raw values appear (D-17).
10. `audit_immutability` — Attempting `UPDATE audit_logs SET details = ...` and `DELETE FROM audit_logs WHERE id = ...` on the rows just written raises the `audit_logs is append-only` exception from migration 0014 (D-18, Phase 9 inheritance).
11. `rls_isolation` — A second compliance client without membership for the smoke user cannot SELECT the extraction artefact written for client A (Phase 9 RLS inheritance, success criterion 7).
12. `cleanup_idempotent` — Smoke deletes its fixture rows in reverse dependency order; running twice in a row yields the same final state.

### Determinism

- The smoke uses a per-run `phase17-smoke-{epoch}` label across client name, user email, and tracked IDs (mirroring Phase 15 pattern) so concurrent runs do not collide and prior runs are easy to garbage-collect by query.
- It sets `RESET ROLE` plus `SET LOCAL row_security = off` to bypass RLS for the fixture setup, then sets the tenant context per call via the same helper Celery uses (`set_tenant_context_for_celery`), so service calls operate under the same RLS the production code does.
- Provider model defaults to `claude-sonnet-4-5` (Phase 16 default), overridable via `ANTHROPIC_MODEL_SMOKE` for forward compatibility.

### Fixture source

Reuses `backend/tests/compliance/extraction/fixtures/gst_drc_01_sample.txt`. No new fixture file. The DRC-01 sample carries notice_number, GSTIN, dates, and amounts, which is exactly the spread the routing gate needs to clear 0.85 on a competent model.

## Decision deltas allowed under "Claude's discretion"

- Order in which the 12 checks run, provided dependencies hold (alembic + columns before any insert; insert before audit; audit before immutability).
- Whether each check returns 1 on the first failure or accumulates all failures and reports a summary (mirrors the Phase 15 smoke choice of fail-fast).
- Cleanup strategy: hard delete of audit rows uses the migrator role bypass since the trigger refuses the migrator-less DELETE; alternative is to leave smoke audit rows in place and tag them so they can be filtered out of dashboards. Choose hard delete via migrator role to keep the smoke idempotent.
