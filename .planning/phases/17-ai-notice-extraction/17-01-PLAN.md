# Plan 17-01: Wave 0 Test Infrastructure (RED state)

**Phase:** 17 (AI Notice Field Extraction, Zero-Shot, BYOK)
**Wave:** 0
**Goal:** Lay frozen test contracts for every behaviour Plans 02 through 07 must satisfy. Every stub starts in RED state via `pytest.skip` or `describe.skip + it.todo`, then flips to GREEN as the corresponding plan lands.

## Why a Wave 0 first

The project convention from Phase 9 and Phase 15 is that Wave 0 freezes the contracts before any service or schema code is written. It does three things:

1. Forces the contract conversations to happen on the test surface, where they are cheapest to revise.
2. Gives every later plan a clear "you are done when this stub turns green" gate.
3. Makes the audit / RLS / immutability guarantees first-class instead of an afterthought.

Wave 0 lands no production code. No new permission row, no migration, no service module. Only test files plus minor scaffolding (test directory, conftest fragment, fixture data) that the later plans will use.

- Permission registration (lands in Plan 17-02).
- Migration (lands in Plan 17-02).

## Success criteria for Wave 0

1. `pytest backend/tests/compliance/extraction/ -q` runs to completion with all 8 tests reporting as SKIPPED, zero failures.
2. `npm --prefix frontend test --run -- --reporter=basic` (once vitest is configured in Plan 17-06) lists the 3 frontend tests as `it.todo`, zero failures.
3. Every stub carries (a) a top-of-file docstring naming the phase + requirement, (b) a `pytest.skip` or `describe.skip` reason that names the Plan number that will land it, (c) an import-or-skip guard so the file does not blow up when the production module does not yet exist.
4. No file in `backend/app/` or `frontend/src/components/compliance/` outside the `__tests__/` folder is modified.

## Risk

The only Wave 0 risk is contract drift between the stub assertions and what Plans 02 to 06 actually need to produce. Mitigated by writing the stubs against the D-IDs in `17-CONTEXT.md` (every assertion cites a D-ID in its docstring) so future drift is visible in a diff.
