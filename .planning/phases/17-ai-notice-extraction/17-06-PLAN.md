# Plan 17-06: Wave 5 Frontend (Upload-first Notice Flow)

**Status:** SHIPPED 2026-05-22
**Phase:** 17
**Wave:** 5
**Goal:** Rewire `/notices/new` from manual-only entry to an upload-first flow, with per-field confidence badges, manual fallback, and a provenance disclosure on the detail page. Keep the existing compliance app design vocabulary; do not introduce a parallel aesthetic.

## Delivered

### 1. API client extension — `frontend/src/lib/api/compliance.ts`

Added 7 new types and 3 new methods:

- Types: `ExtractedFieldDto`, `ExtractionEnvelopeDto`, `ExtractionRouteDecisionDto`, `ExtractPreviewResponse`, `ExtractionResponseDto`, `AcceptExtractionItem`. Plus `CreateNoticePayload` re-export.
- Methods: `extractPreview(file)`, `getExtraction(id)`, `acceptExtraction(id, items)`.
- `ComplianceNotice` type (in `frontend/src/types/compliance.ts`) gained the 5 Phase 17 fields (`extracted_fields`, `extraction_confidence`, `extracted_by_provider`, `extracted_at`, `extraction_status`).

### 2. Per-field row component — `frontend/src/components/compliance/ExtractedFieldRow.tsx`

Wraps each form input with a confidence pill (green `Confident` ≥ 0.75, amber `Review` ≥ 0.55, rose `Needs review` < 0.55 per D-08), source-span tooltip (D-34 hover copy), discard / restore actions, and an `Edited` chip when the user-edited value diverges from the extracted value (so the save-time audit row records `was_edited=true` per D-17).

Visual treatment matches the existing `ConfidenceBadge` and `StatusPill` patterns: rounded-full pill, semantic emerald / amber / rose backgrounds, tabular-nums for percentage. Cursor-pointer + focus-ring + 200ms transitions per ui-ux-pro-max checklist.

### 3. Orchestrator — `frontend/src/components/compliance/ExtractionPreviewForm.tsx`

Three states on one page (D-26):

1. **Empty**: full-bleed dashed dropzone hero with `FiUploadCloud`, primary CTA "Drop a notice PDF, JPG, or PNG to auto-fill the form", secondary link "Fill manually instead".
2. **Extracting**: dropzone collapses to a chip showing the filename; an indeterminate pulsing progress strip appears below.
3. **Extracted**: form fields populated; each row wraps `ExtractedFieldRow` with its extracted value + confidence badge; "Save notice" button at the bottom.

State management: `useMutation` for both extract-preview and save. Failure handling: HTTP 412 with `code: "no_ai_credential"` flips to manual mode + shows an inline amber banner pointing at `/dashboard/settings/ai-credentials` (D-30). Any other error toasts and drops to manual.

Save flow (3 round-trips when a file was dropped):
1. `complianceApi.createNotice(payload)` with the user-final values.
2. `complianceApi.uploadNoticeFile(notice.id, fileObj)` so the file persists.
3. `complianceApi.acceptExtraction(notice.id, items)` so per-field audit rows land + `extraction_status='accepted'`.

Each step is independently fault-tolerant: a failed upload toasts but the notice still saves; a failed accept logs an info toast and the next visit to the detail page can complete acceptance.

### 4. Page rewrite — `frontend/src/app/dashboard/compliance/notices/new/page.tsx`

Was a 290-line monolith of manual form fields. Now a 50-line page that:

- Guards on `activeClientId === null` (unchanged).
- Renders the page title, back-to-dashboard link, and `<ExtractionPreviewForm activeClientId={activeClientId} />`.
- The old manual-only form is gone — its fields live inside `ExtractionPreviewForm`, which serves both the upload-first and manual-fallback flows.

### 5. Provenance disclosure — `frontend/src/components/compliance/ExtractionProvenanceDisclosure.tsx`

Collapsible section on the notice detail page (D-28). When expanded, fetches `GET /notices/{id}/extraction` (TanStack Query, enabled-on-open + 60s staleTime). Renders provider, model, average confidence, extracted_at, and a per-field list with confidence percentages + a small amber info icon for fields carrying a `validation_failure`. Renders nothing when `extraction_status` is null — manually-created notices stay uncluttered.

### 6. Detail page wire-up — `frontend/src/app/dashboard/compliance/notices/[id]/page.tsx`

Added the disclosure between `NoticeAISection` (Phase 16) and `ActivityTimeline`. Imports the new component, passes `noticeId` and `hasExtraction={Boolean(notice.extraction_status)}` so the disclosure stays invisible on legacy notices.

## Decision deltas during Plan 17-06

- **Did not switch from /new modal to a brand-new route.** The user already has muscle memory hitting `/notices/new` from the dashboard CTA. Rewiring the route preserves discoverability and link backwards-compat.
- **Did not introduce a separate "Extracting…" full-screen modal.** A pulsing progress strip + chip is the lighter-weight pattern that matches `FileDropzone`'s existing "Uploading…" treatment. Modals fragment focus.
- **Did not unify the confidence-pill component with the existing `ConfidenceBadge.tsx`.** That component is shaped around Phase 10's classifier (authority confidence + type confidence pair), not Phase 17's per-field LLM confidence. Forcing one component to serve both shapes would require a prop union that obscures both call sites. `ExtractedFieldRow` is the per-field shape; `ConfidenceBadge` stays the per-classification shape. A future plan can merge them if the visual language drifts.
- **Did not use `aidesigner` MCP or `21st.dev` magic components.** Both produce designs from scratch; the project has a mature design system already. Using them in this wave would have introduced visual debt across 14 phases of existing components.
