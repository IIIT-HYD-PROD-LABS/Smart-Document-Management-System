# Plan 17-03: Wave 2 Extractor Service, Prompt, Validator, Router

**Status:** SHIPPED 2026-05-22
**Phase:** 17
**Wave:** 2
**Goal:** Land the four pure service modules that own the extraction pipeline from text in to envelope out, without touching the HTTP surface or Celery.

## Delivered

1. `backend/app/compliance/services/notice_extraction_prompt.py`
   - `FIELD_SCHEMA` dict, 14 canonical keys with one-line hints.
   - `MAX_TEXT_WINDOW = 4000` per D-15.
   - `build_user_prompt(text)` assembles the user message with the envelope-shape instructions D-03 spells out and the precision-over-recall rule D-05.
   - Does NOT redefine a SYSTEM prompt: extraction reuses `ai_service.SCOPE_LOCK_SYSTEM` per D-13.

2. `backend/app/compliance/services/notice_extraction_validator.py`
   - `validate_and_score(envelope)` pure function. Returns a deep-copied envelope with post-validation confidences and `validation_failure` annotations.
   - Single-field rules: GSTIN (regex + state code), PAN, CIN, ISO date, authority enum, non-negative number for tax / interest / penalty / total.
   - Cross-field rules: deadline must be later than issued, total liability must equal tax + interest + penalty within 1 INR.
   - Failures: original confidence preserved on `original_confidence`, `confidence` halved per D-33. Recomputes `average_confidence` over the post-validation set.

3. `backend/app/compliance/services/extraction_routing_service.py`
   - `AVG_GATE = 0.85`, `CRITICAL_GATE = 0.85`, `CRITICAL_FIELDS = ("notice_number", "authority")`.
   - `route_or_apply(envelope)` returns the D-06 conjunctive decision (`apply` vs `review_queue`) with a human-readable failure reason and the critical-field confidences.

4. `backend/app/compliance/services/notice_extractor_service.py`
   - `extract_notice_fields(db, *, client_id, user_id, text, notice_id=None)` is the single entry point.
   - Resolves `AICredential` via `ai_service.get_credential`. Missing → raises `NoticeExtractionCredentialMissingError` (D-14).
   - Builds provider via `ai_service._build_active_provider`, runs `ai_service._run(provider, build_user_prompt(text), max_tokens=2048)`. OUT_OF_SCOPE sentinel bubbles up as `AIOutOfScopeError`.
   - Parses JSON envelope via `ai_service._parse_json_or_default`. Unparseable → `NoticeExtractionParseError`. Both raise paths still write a redacted audit row carrying the failure mode.
   - Filters returned fields down to `FIELD_SCHEMA` keys (D-04). Drops anything the model invents.
   - Runs `validate_and_score`. Writes one immutable audit row with `action='notice_ai_extract'` and PII-redacted args.
   - Returns the validated envelope.

## Why no router or Celery in Wave 2

- Keeps the contract under unit-test discipline before HTTP shape is locked. The Wave 0 stubs that exercise this service all flipped GREEN this wave.
- Router + Celery introduce request-scoped dependencies (auth, RLS context, rate limiter). Bundling them now would muddy the failure surface; if a Wave 4 router test fails, we want to know it is router-shaped, not extractor-shaped.

## Verification

## Decision delta during Plan 17-03

- **No new SYSTEM prompt module.** The Wave 0 stub originally asserted `from notice_extraction_prompt import SYSTEM_PROMPT`. That asserted the wrong contract — D-13 explicitly reuses `SCOPE_LOCK_SYSTEM`. The stub was inverted in Wave 2: `test_extraction_does_not_redefine_system_prompt` now FAILS if anyone reintroduces a Phase 17 SYSTEM_PROMPT. Defends D-13 against future drift.
- **`mock_provider_factory` fixture corrected.** The Wave 0 stub mocked `provider.complete_json` (a non-existent method). Real `AIProvider.complete` returns a string; the fixture now mocks `provider.complete.return_value = json.dumps(...)` to match.
