# Phase 10 Plan 02 — Auto-Escalation on Critical Risk

## Wave: 2 of 3 (within v2.0 ship of Phase 10)

## Goal

RISK-04: Critical-risk notices auto-escalate to the Compliance Head role.
v2.0 lands the **escalation logic** — assignment + audit + activity timeline.
The cross-channel **alert delivery** (email/SMS/push) is Phase 11's job; this
plan emits the activity row that Phase 11 will subscribe to.

## Scope

**In scope:**
1. `escalation.should_escalate(db, notice, assessment) -> bool`
   - Returns True iff `assessment.tier == "critical"` AND no NoticeActivity row
     with `event_type="escalated"` exists for this notice within
     `ESCALATION_COOLDOWN` (24 hours).
2. `escalation.escalate(db, notice, assessment, system_user) -> None`
   - Looks up the Client's compliance_head (first user with role
     `compliance_head` in client_memberships)
   - Writes NoticeActivity row: `event_type="escalated"`, payload includes
     `risk_score`, `risk_tier`, `top_factors`, `assigned_to_user_id`
   - Writes AuditLog row: `action="notice_escalated"`, `details={before_value: notice.assigned_user_id, after_value: head_user_id, reason: "critical_risk"}`
   - Optionally reassigns `notice.assigned_user_id = head_user_id` (Phase 9
     D-25: assignment is mutable on ComplianceNotice; this is the legitimate
     auto-reassignment path)
3. Wire-in in `compliance_tasks.classify_and_score_notice`:
   - After `db.commit()` of risk_score + tier, if `assessment.tier == "critical"`,
     check `should_escalate` and call `escalate` in a separate transaction.
   - Failure to escalate is non-fatal (logged) — the risk score is the
     primary contract.
4. Special case: **no compliance_head exists for the client** — log a warning,
   write the NoticeActivity + AuditLog rows anyway with `assigned_to_user_id=NULL`,
   and surface this in the next plan's frontend as "Critical: needs assignment".

**Out of scope:**
- Cross-channel alert delivery (email/SMS/push) — Phase 11 owns this
- Per-client escalation chain configuration UI — Phase 11 owns this; v2.0 uses
  default chain (compliance_head only)
- External counsel escalation — Phase 11 + Phase 12

## Risks

- **Risk:** Escalation transaction failure could leave risk score persisted
  without escalation. **Mitigation:** That's the desired behavior. Risk score
  is the system-of-record fact; escalation is a derived action that can be
  retried via the daily `recompute_all_risk_scores` cron (which calls
  classify_and_score_notice → escalation again with cooldown enforced).
- **Risk:** `should_escalate` querying NoticeActivity could be slow at scale.
  **Mitigation:** NoticeActivity already has index on `notice_id` from
  migration 0013. Add filter on `event_type` to use index range scan.
