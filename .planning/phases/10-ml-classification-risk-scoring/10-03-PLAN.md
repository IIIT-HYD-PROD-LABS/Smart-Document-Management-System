# Phase 10 Plan 03 — Frontend Review Queue + SHAP UI

## Wave: 3 of 3 (within v2.0 ship of Phase 10)

## Goal

Surface the Phase 10 ML outputs (rule-based for v2.0) in the UI:
- Risk score + tier with explainable "why" panel on every notice detail page
- Critical tier visually distinct (subtle pulse, not garish)
- Review queue page where compliance_head/ca_consultant resolve low-confidence
  classifications (route exists for v2.1 BERT outputs; for v2.0 the queue stays
  empty by design)

## Scope

**In scope:**
1. `frontend/src/components/compliance/ConfidenceBadge.tsx` — pill showing
   "GST DRC-01 · 91%" with hover tooltip "Authority: 0.94, Type: 0.91"
2. `frontend/src/components/compliance/WhyThisRiskScore.tsx` — collapsible
   `<details>` panel rendering `top_factors[].natural_language` as a 3-bullet
   list, with the raw score + tier in the summary line
3. Update `frontend/src/components/compliance/RiskTierDot.tsx` — add `critical`
   variant with subtle Tailwind animate-pulse + animate-duration-2s. Avoid
   blinking (WCAG 2.3.1).
4. `frontend/src/app/dashboard/compliance/notices/[id]/page.tsx` — render
   ConfidenceBadge in header (next to AuthorityBadge) and WhyThisRiskScore in
   the right column near MetadataPanel.
5. `frontend/src/app/dashboard/compliance/review/page.tsx` — list page:
   - Table columns: Notice #, Predicted Authority, Type, Confidence, Received, Assign
   - Per-row "Assign" action opens dialog with authority + type dropdown
   - Empty state: "No notices currently need review. Reviewer queue surfaces low-confidence ML predictions (Phase 10 v2.1)."
   - Pagination via complianceApi
6. Sidebar nav entry — only visible to users with `NOTICE_REVIEW` permission
   (use existing role-gate pattern from Phase 9 sidebar)
7. Frontend types in `frontend/src/types/compliance.ts`:
   - `ReviewQueueItem`, `ReviewAssignRequest`
8. `frontend/src/lib/complianceApi.ts` — add `reviewQueue` namespace with
   `listPending`, `assign`

**Out of scope:**
- Bulk assign (defer to v2.1 once volume justifies)
- Confusion matrix dashboard (Phase 13 reporting)

## Acceptance

1. Notice detail page renders confidence badge + "Why this risk score?" panel
2. Critical-tier notice has subtle pulse animation (no flashing/blinking)
3. Review queue page renders empty state with v2.1 deferred messaging
4. Sidebar shows "Review Queue" nav entry for compliance_head + ca_consultant only
5. `npm run build` clean (no TypeScript errors)
6. Manual smoke: navigate to a notice → see confidence (NULL for v2.0 → badge
   shows "Manual entry · 100%") + risk_score panel; navigate to /review → empty state

## v2.0 visual contract

- ConfidenceBadge: `Manual entry` label when classifier confidences are NULL;
  `BERT v1` label once v2.1 lands. Color-coded:
  - ≥0.90 → green
  - 0.75–0.89 → amber
  - <0.75 → red (with "Needs review" text)
- WhyThisRiskScore summary: `Risk: {score} ({tier})` with a chevron to expand
- Top 3 factors rendered as plain `<li>` text — no chart libraries (keep
  bundle small; Phase 13 owns analytics charts)

## Risks

- **Risk:** Pulse animation triggers vestibular discomfort. **Mitigation:**
  Tailwind's `motion-safe:` modifier + `animate-pulse` (gentle opacity, not
  bouncing). Honor `prefers-reduced-motion`.
- **Risk:** WhyThisRiskScore depends on `notice.risk_factors` shape that the
  backend returns in compliance_tasks but doesn't currently persist on the
  notice row. **Mitigation:** Persist `top_factors` into `ner_extracted_fields`
  JSONB key (already exists from migration 0020). Update Plan 10-01 task scope
  if needed (verify in execution).
